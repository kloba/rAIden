# results/

Everything here comes from the recorded Azure battle; nothing is hand-edited.

| Path | What it is |
|---|---|
| `SCOREBOARD.md` | per-round table (wake, first clue, time to a green oracle, turns, tool calls, denials, restarts, tokens), the final reconcile verdict, the files rAIden wrote itself, and the guardrail denials. Generated by `arena/report.py` |
| `RUN-HISTORY.md` | the four full runs: what each one exposed (a real PostgreSQL hang, a benign log line counted as a crash, a stale-state flapping bug, a bug in my own attack script) and what was fixed before the recorded run |
| `RUN1-HUNG-POSTMASTER.md` | what the *first* full run taught us: a real PostgreSQL 18.6 hang during crash recovery, the three guardrail refusals, and the fixes that followed |
| `bundle/battle.json` | the referee's raw scoreboard (`arena/battle.py`) |
| `bundle/arena-events.jsonl` | the referee's event log: attacks, `bomb_armed` / `bomb_defused` / `attack_prevented`, round results |
| `bundle/timeline_10s.json` | acknowledged commits per 10 s, the application's own view of every outage (the chart on slide 4) |
| `bundle/incidents/*/` | per incident: `report.md` (written by the agent), `notes.md` (its working notes), `incident.json` (turns, tool calls, tokens), `evolve.json` |
| `bundle/new/` | the checks and runbooks rAIden wrote *itself* during the fight, as they were at the end |
| `bundle/audit.jsonl` | every tool call the guard judged, allow or deny, with the rule |
| `bundle/tool-timeline.jsonl` | compact timeline of agent tool calls, incidents, patrols and evolve sessions |
| `bundle/pg-log-highlights.jsonl`, `storm.json` | the PostgreSQL log lines shown on the slides and the size of the crash storm |
| `bundle/lessons.md`, `evolution.md`, `patrol.log` | the agent's memory files |

How it was produced: `deploy/vm/bundle.sh` (on the lab VM) -> `deploy/vm/fetch.sh` (through Azure Run Command, about 4 KB per call) ->
`python3 arena/report.py results/bundle`.

Read it with the usual caveats: one run is one sample of a non-deterministic model; the referee (a client-side ledger of acknowledged
commits plus `pg_amcheck`) judges the database, not the agent's opinion; times include the debounce window (the agent wakes after a storm
has been quiet for 6 s or has lasted 15 s) and the post-fix verification window.
