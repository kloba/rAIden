# Recorded chaos test results

Everything here comes from the recorded run of the [chaos test](../../../docs/chaos-tests.md) on Azure; nothing is hand-edited.

| Path | What it is |
|---|---|
| `SCOREBOARD.md` | per-round table (wake, first clue, time to a green oracle, turns, tool calls, denials, restarts, tokens), the final reconcile verdict, the files rAIden wrote itself, and the guardrail denials. Generated by `tests/chaos/report.py` |
| `RUN-HISTORY.md` | the runs before the recorded one: what each exposed (a PostgreSQL shutdown that hung under pg_crash, a benign log line counted as a crash, a stale-state flapping bug, a bug in my own attack script, a race in the referee) and what was fixed before the recording |
| `RUN1-HUNG-POSTMASTER.md` | what the *first* full run taught us: a PostgreSQL 18.6 fast shutdown that hung during crash recovery while pg_crash was firing (not proven to be a PostgreSQL bug), the three guardrail refusals, and the fixes that followed |
| `bundle/battle.json` | the referee's raw scoreboard (`tests/chaos/battle.py`) |
| `bundle/arena-events.jsonl` | the referee's event log: attacks, `bomb_armed` / `bomb_defused` / `attack_prevented`, round results |
| `bundle/timeline_10s.json` | acknowledged commits per 10 s, the application's own view of every outage |
| `bundle/incidents/*/` | per incident: `report.md` (written by the agent), `notes.md` (its working notes), `incident.json` (turns, tool calls, tokens), `evolve.json` |
| `bundle/new/` | the checks and runbooks rAIden wrote *itself* during the run, as they were at the end |
| `bundle/audit.jsonl` | every tool call the guard judged, allow or deny, with the rule |
| `bundle/tool-timeline.jsonl` | compact timeline of agent tool calls, incidents, patrols and evolve sessions |
| `bundle/pg-log-highlights.jsonl`, `storm.json` | the PostgreSQL log lines picked out of the run and the size of the crash storm |
| `bundle/lessons.md`, `evolution.md`, `patrol.log` | the agent's memory files |

How it was produced: `deploy/vm/bundle.sh` (on the lab VM) -> `deploy/vm/fetch.sh` (through Azure Run Command, about 4 KB per call) ->
`python3 tests/chaos/report.py`.

Read it with the usual caveats: one run is one sample of a non-deterministic model; the referee (a client-side ledger of acknowledged
commits plus `pg_amcheck`) judges the database, not the agent's opinion; times include the debounce window (the agent wakes after a storm
has been quiet for 6 s or has lasted 15 s) and the post-fix verification window.
